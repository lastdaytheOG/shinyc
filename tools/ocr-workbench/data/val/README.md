# `data/val/` — **E1**, the golden validation set

**You supply this. It is the single most important asset in the project and nothing blocks it.**

Per asset guide §9: *"If you do exactly one thing from this document, do step 6."* This is step 6.

Without E1, every accuracy claim about NPU OCR — better, worse, same as ML Kit — is unverifiable,
and there is no way to decide go/no-go. It cannot be automated, generated, or parallelized away,
because its whole value is that a **human** verified the text.

---

## Tooling — you do not crop anything by hand

```bash
cd tools/ocr-workbench/scripts

# 1. pages -> line crops + a blank ground_truth.tsv   (no OCR, nothing pre-filled)
python 08_make_lines.py --pages ../data/val/_staging --out ../data/val/hi \
                        --script hi --stratum clean

# 2. ...you transcribe ground_truth.tsv...

# 3. check it before trusting any number it produces
python 09_validate_e1.py --dir ../data/val/hi

# 4. emit the app's GoldenDataset format + media
python 10_tsv_to_golden.py --dir ../data/val/hi --dir ../data/val/en --out ./e1_golden --name e1
adb push e1_golden/e1.json /data/data/com.amar.vault/files/benchmark/GoldenDataset/
adb push e1_golden/media   /data/data/com.amar.vault/files/benchmark/GoldenDataset/
```

Step 4 needs no rebuild — `GoldenDatasetStore` merges `filesDir/` over the packaged assets, so
transcribe → push → measure is a fast loop.

## Layout

```
data/val/
  _staging/                 captured pages, before splitting
  en/
    images/     line_00001.png …   natural resolution — read THESE while transcribing
    images_h48/ line_00001.png …   height-normalized to 48px (recognizer input height)
    ground_truth.tsv
    e1_manifest.json        checksums, bboxes, provenance, duplicate groups
    duplicates.tsv          only written if duplicates were found
  hi/  … same shape …
  pages/
    en/  page_0001.png  page_0001.txt  ...
    hi/  page_0001.png  page_0001.txt  ...
```

Two image sets exist because they serve different consumers: `images_h48/` matches the
recognizer's fixed input height, but the app benchmark feeds `mediaFile` to
`ImageContentExtractor`, which does its own preprocessing — handing it a pre-shrunk 48 px image
would degrade ML Kit for a reason unrelated to ML Kit, and ML Kit is the baseline every gate is
measured against. `10_tsv_to_golden.py` therefore ships the natural crops.

## Line-level set — `en/` and `hi/`

| Property | Spec |
|---|---|
| Count | **50–200 transcribed lines per script** |
| Images | One cropped text line per file, PNG, from your real corpus |
| Content | Stratified: clean digital, scanned/noisy, small text, table cells, headings, **and mixed EN+HI lines** |
| Labels | Human-verified exact transcription, **NFC-normalized** (the app already NFC-normalizes OCR output — if the ground truth is NFD, every Devanagari line scores as wrong) |

`ground_truth.tsv` — tab-separated, **UTF-8, no BOM**, with a header row. Generated by
`08_make_lines.py` with column 2 blank; you fill column 2 only:

```
image	transcription	script	stratum
images/line_00001.png	The quick brown fox	en	clean
images/line_00002.png	वाक्य का पाठ	hi	scanned
```

The separator is a literal TAB — transcriptions contain spaces, so a space-separated file
mis-parses silently. `script` and `stratum` are pre-filled from the `--script` / `--stratum`
flags; correct any row where the default is wrong.

Leave a row blank to skip it — blank rows are reported as untranscribed and excluded from the
generated dataset rather than shipped as empty ground truth.

## Page-level set — `pages/`

| Property | Spec |
|---|---|
| Count | **10–20 full pages per script** |
| Images | Full rendered page PNG, same dpi as C1 |
| Labels | `page_0001.txt` next to each image — the full page text in **correct reading order** |

Reading order is the reason page-level ground truth exists separately. A detector plus a line
sorter can be *per-line perfect* and still scramble a two-column page into nonsense. ML Kit does
reading order for us today; NPU OCR means we own it. **Include multi-column pages from day one**
or the regression will not show up until integration.

## The rule that protects every number downstream

**E1 is never used for calibration or fine-tuning.** Not once, not "just the leftovers."
Split by **document**, not by page — two pages from the same book share fonts, layout, and scan
quality, so a page-level split leaks. Record which documents went to E1 vs C1.

## Bootstrapping the transcription faster

Do not type from scratch. Run the existing ML Kit path over the crops, dump its output as a
pre-fill, and **correct** it. That is 3–5× faster than typing. Correcting is still human
verification; accepting uncorrected output is not — if you skip the correction pass, you have
measured NPU OCR against ML Kit's mistakes, and it will score suspiciously perfect.
