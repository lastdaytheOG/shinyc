# Agent Runtime Deferral & Preservation Guide

This document preserves the architecture, components, and reintegration mapping of the **Agent Runtime** subsystem, which has been temporarily decoupled to stabilize compilation for the **Search MVP**.

---

## 1. Context and Deferral Decision

The Agent Runtime (historically under `com.amar.vault.agent.*`) was designed to capture accessibility events, track active screen hierarchies, and inject synthetic interactions (e.g. searching/typing/clicking inside external applications). 
For the **Search MVP**, the core objective is on-device semantic and lexical indexing of local user files (receipts, screenshots, documents) and displaying these in a custom Home and Search UI. Because the Search MVP does not depend on target-app navigation or action execution, the Agent Runtime has been formally deferred to Phase 4 (Model Runtime and Agent Integration) to allow stabilization of the core search pipeline.

## 2. Missing Components & Inventory

Below is a complete inventory of the decoupled components, their original locations, and their purposes:

| Component Type | Original Package / Class | Usage Purpose |
|---|---|---|
| **Reducer Engine** | `com.amar.vault.agent.runtime.reducer.ReducerEngine` | Collects UI snapshot events, processes state changes, and updates the central WorldState. |
| **Accessibility Event Bus** | `com.amar.vault.agent.runtime.events.AccessibilityEventBus` | Dispatches accessibility events from the perception service to runtime collectors. |
| **IME Coordinator** | `com.amar.vault.agent.runtime.ime.ImeCoordinator` | Monitors virtual keyboard state, active cursors, and text selection boundaries. |
| **Semantic Bridge** | `com.amar.vault.agent.runtime.semantic.SemanticBridge` | Resolves standard layout elements to functional roles (e.g. identifying a Search Box role). |
| **Metrics Collector** | `com.amar.vault.agent.runtime.metrics.InjectionMetrics` | Measures execution latency, interaction success rate, and injection errors. |
| **Overlay Detector** | `com.amar.vault.agent.runtime.recovery.OverlayDetector` | Detects overlapping alert dialogs or system sheets that might block clicks. |
| **Recovery Engine** | `com.amar.vault.agent.runtime.recovery.RecoveryEngine` | Re-runs failed interaction steps, recovers from stalls, or reverts app states. |
| **Phase Orchestrator** | `com.amar.vault.agent.runtime.orchestrator.PhaseOrchestrator` | Coordinates discrete stages of step execution (e.g., waiting for input, typing text). |
| **Replay Recorder** | `com.amar.vault.agent.runtime.replay.EventHistoryRecorder` | Saves screenshots and node hierarchies to trace runs during offline debug sessions. |
| **Adapter Loader** | `com.amar.vault.agent.runtime.adapters.AdapterManifestLoader` | Discovers and parses declarative JSON app rules for injection coordinates. |
| **Adapter Registry** | `com.amar.vault.agent.runtime.adapters.FrameworkAdapterRegistry` | Matches active package names to application-specific adapters (WhatsApp, ChatGPT, etc.). |
| **Telemetry Exporter** | `com.amar.vault.agent.runtime.telemetry.TelemetryExporter` | Exports JSON workflow execution runs to local storage folders. |
| **World State Store** | `com.amar.vault.agent.runtime.state.WorldStateStore` | In-memory singleton caching the last known snapshot of the active application. |
| **Perception Service** | `com.amar.vault.agent.perception.PerceptionService` | Android AccessibilityService that consumes node updates from the OS window manager. |
| **Activity Tracker** | `com.amar.vault.agent.CurrentActivityHolder` | Caches a weak reference to MainActivity to launch target apps from foreground focus. |
| **App Indexer** | `com.amar.vault.agent.intent.AppIndex` | Hydrates list of launchable intents on the user's phone to verify routing. |
| **Debug UI Screens** | `com.amar.vault.agent.debug.*` | Interactive layouts (`DebugAgentScreen`, `DebugBrainScreen`) to test models and steps manually. |

## 3. Historical Evidence

* **Log Evidence**: Commit history, `raw.log`, and `full.log` files contain active logging statements generated by `ReducerEngine` (e.g., `ReducerEngine: REDUCED seq=678 type=WindowContentChanged pkg=com.amar.vault ime=false`).
* **Source Tracking**: `pkg.log` records code paths and files originally compiled under the `app/src/main/java/com/amar/vault/agent/` directory, confirming a complete implementation existed.

## 4. Reintegration Points

To restore the Agent Runtime in the future, the following files must be updated:

1. **[AmarApplication.kt](file:///d:/Version1/app/src/main/java/com/amar/vault/AmarApplication.kt)**
   - Un-comment the import: `import com.amar.vault.agent.runtime.reducer.ReducerEngine`.
   - Un-comment the `@Inject lateinit var` fields for the 13 agent components.
   - Un-comment the initialization block in `onCreate()` that starts the engines, registers the PerceptionService binding, and initializes telemetry.

2. **[MainActivity.kt](file:///d:/Version1/app/src/main/java/com/amar/vault/MainActivity.kt)**
   - Un-comment imports for `CurrentActivityHolder` and `AppIndex`.
   - Un-comment `AppIndex.attach(applicationContext)` in `onCreate()`.
   - Un-comment `CurrentActivityHolder.set(this)` in `onResume()` and `CurrentActivityHolder.clear(this)` in `onPause()`.

3. **[VaultNavHost.kt](file:///d:/Version1/app/src/main/java/com/amar/vault/VaultNavHost.kt)**
   - Un-comment imports for `DebugAgentScreen` and `DebugBrainScreen`.
   - Replace the placeholder Compose `Text` screens for `Screen.AGENT_DEBUG` and `Screen.BRAIN_DEBUG` with calls to `DebugAgentScreen()` and `DebugBrainScreen()`.

4. **[AndroidManifest.xml](file:///d:/Version1/app/src/main/AndroidManifest.xml)**
   - Un-comment the Accessibility Service configuration tag `.agent.perception.PerceptionService`.
   - Un-comment the debug receiver declarations `.agent.runtime.replay.EventHistoryDebugReceiver` and `.agent.runtime.telemetry.TelemetryDebugReceiver`.

## 5. Phase 4 Implementation Plan

Once Phase 4 is reached:
1. **Source Restore**: Import/restore the `com.amar.vault.agent` package directory back into the source tree.
2. **Restore Integration**: Re-enable the reintegration points detailed in Section 4 of this document.
3. **Verify DI Context**: Ensure Hilt correctly binds implementation modules for the injected components (such as `AccessibilityEventBus` and `ReducerEngine`).
4. **Validation Test**: Enable the accessibility service on a test device, and run the developer screens from the settings menu to confirm event flows.
